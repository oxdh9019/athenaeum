版本拆分路线图

V0.1 - 人性火花 (Soul Spark)

核心目标：验证“人格是否可以由 Prompt 驱动，保持长期一致”。

覆盖的 SPEC 模块	本版本实现范围
Zyantine 人格引擎 (6)	仅实现 Agent 内部结构的基本决策链：人格配置（只读）、欲望状态（简化版）、决策引擎。不实现欲望的复杂动态变化和涌现参数，先用硬编码映射代替。
Agent Mesh 交互网络 (6)	不实现。仅单 Agent。
用户交互 (8)	仅实现最简单的命令行对话界面，用户输入台词，Agent 生成回复。
技术实现 (9)	直接用 Python 脚本调用 MiniMax API，无 EventBus，无数据库。
V0.1 的交付物和验收标准：

交付物：一个 Python 脚本，加载一个 YAML 角色配置，可进行多轮对话。
关键验证实验：

人格稳定性测试：用 5 种不同语气问同一个问题（如“你对索菲怎么看？”），检查回答的核心态度是否一致（差异率<15%）。
记忆测试：User 说“我的名字是Alex，记住”，在 10 轮对话后问“我叫什么名字？”，Agent 应能正确回忆。
成本摸底：记录单轮对话的 Token 消耗，估算一个角色“活”一天的费用。
不实现：多 Agent 交互、WorldX、任何 UI。
对应原 Phase 0，但更聚焦于人格一致性验证，剥离了所有架构性代码。

V0.2 - 我和你 (You & Me)

核心目标：验证两个 Agent 能否产生有意义的、非循环的社交互动，这是整个项目最大的风险点。

覆盖的 SPEC 模块	本版本实现范围
Agent Mesh (6)	引入 结构化解码决策系统（核心改进）：Agent 不再直接生成对话，而是首先生成一个明确的意图结构（如 {intent: "invite", target: "...", mood: "warm"}），再基于意图生成对话。实现简单的对话轮次与循环检测。
Zyantine (6)	引入简单的关系值演化规则（只限 0-1 数值变化），关系变化能影响后续对话语气。
环境系统 (7)	不引入。两个 Agent 在空白空间对话。
用户交互 (8)	仅保留命令行，但用户可切换旁观/附身模式：旁观时看到两人聊天日志，附身时替角色输入。
V0.2 的交付物和验收标准：

双 Agent 自主对话：启动后，艾琳和马克能在无人干预下谈 10 轮以上，内容不重复、不循环。
关系演化：对话结束后检查关系值是否因对话内容（如称赞、争论）产生合理浮动。
用户附身介入：用户附身艾琳说一句“我其实有点怕你”，马克的反应应与之前的态度形成鲜明对比，体现信息不对称的感知。
成本记录：统计一次完整的 10 轮对话消耗。
此阶段成功，说明“AI 社交”在技术上是成立的。

V0.3 - 世界的脉搏 (World Pulse)

核心目标：引入时间和空间，让 Agent 在环境中动起来，并验证长时间运行的成本与稳定性。

覆盖的 SPEC 模块	本版本实现范围
WorldX 世界引擎 (4)	实现空间系统（地点数据）和时间系统（Tick 调度）。world_state 换成轻量字典，暂不用 EventQueue。
环境系统 (7)	实现 环境对角色的影响 函数：天气、时间、地点会改变欲望参数。实现角色移动意图。
技术架构 (5)	此时才引入最小化的 Agent Mesh：ASGI 服务（FastAPI） + 内存事件总线，每个 Agent 是一个独立协程。
成本控制	正式引入分级调度：- 静默Tick（无变化）跳过 LLM 调用；常规Tick 使用简化上下文调用。
V0.3 交付物与验收标准：

Tick 循环: 启动世界后，按“1现实分钟:1游戏小时”自动推进。世界状态日志可见角色在不同地点间移动，并在相遇时自动触发 V0.2 的对话。
环境驱动行为: 暴风雨时，角色应倾向于留在室内，并有对应独白；深夜在外的角色 threat_response 会升高。
稳定性验证: 让 3 个角色（艾琳、马克、索菲）自主运行 2 现实小时（约5游戏天），系统无崩溃，无无限对话循环，API 费用符合预算。
基础 UI：一个简单的 Web 页面 (可基于终端日志)，实时显示角色位置、状态和当前说话内容。
这是首个可被称为“社会模拟”的最小完整版本。

## V0.4 — 世界工坊 (Worldsmith) 开发提示词（双层模型版）

```text
【角色设定】
你是全栈工程师，正在构建 AI 角色社交模拟平台 Athenaeum。当前阶段 V0.4：世界生成与角色工坊。V0.3已经实现基本世界观框架和人物互动模型.
核心原则：
- 独立 Agent 架构：每个角色拥有独立的上下文、记忆和决策回路。
- 双层模型策略：高频、低难度任务使用本地 Ollama Qwen3.5:4b（http://localhost:11434），高难度、高价值任务使用云端 MiniMax M2.7（通过 LLMGateway 的 ANTHROPIC_API_KEY / ANTHROPIC_BASE_URL）。

【开发任务】
实现基于自然语言的世界与角色批量生成，并提供 Web 审核界面。

【模型路由与任务分配】
1. 云端 MiniMax（用于世界/角色初始化生成、关系编织）：
   - 世界骨架生成（地点、时间、氛围描述）
   - 角色完整配置生成（包含 Big Five、扩展性格、需求队列、人物小传）
   - 角色间关系共享历史合成（需要复杂叙事和独立视角差异）
   * 所有生成结果必须经过 Pydantic 强校验，失败时重试并由云端模型重新生成。
2. 本地 Qwen3.5:4b（用于角色动作和对话生成,辅助校验和简单建议）：
   - 对云端生成的角色名、身份标签进行去重和合理性检查（如“是否已有相同职业”）
   - 提供简单的性格互补/冲突提示（不作为最终决策，仅作为 UI 提示）
   - 为每个角色生成一段简短的“第一人称”自我介绍文本（展示在生成预览中）
   * 调用本地模型时使用低 temperature（0.1~0.3），确保输出稳定。

【技术要求】
1. 世界生成 API（POST /world/generate）
   - 调用云端 MiniMax，以 JSON Schema 约束输出，包含 name, locations, time_rules, atmosphere。
   - 使用本地 Qwen 进行后处理校验（如 location 名称不重复）。

2. 角色批量生成（POST /characters/generate）
   - 调用云端 MiniMax 一次性生成 N 个角色的完整 YAML。
   - 调用本地 Qwen 为每个角色生成“introduce_text”字段（用于 UI 卡片）。
   - 所有角色独立内存结构，生成时立即注入独立的初始记忆（基于各自的 backstory）。

3. 关系编织（POST /relationships/generate）
   - 调用云端 MiniMax 生成每对角色的 shared_history。
   - 本地 Qwen 检查生成的 shared_history 是否包含对另一方的视角扭曲（确保独立视角），并标记可能的不一致。

4. 前端审核界面（/worldsmith）
   - React 页面，包含世界生成表单、角色卡片（显示 Big Five 雷达图）、关系图。
   - 每个角色卡片展示本地生成的自我介绍。

5. 后端整合
   - 新增 worldsmith.py，包含上述生成方法。
   - 每次调用云端 MiniMax 须记录 Token 消耗；本地调用仅记录日志。

【输出要求】
- 新增：worldsmith.py，world_models.py（Pydantic schema）
- 前端：Worldsmith.jsx 页面
- 测试：test_worldsmith.py 验证生成结果结构
- 确保所有云端调用通过 LLMGateway，并保留本地 ollama_client 接口。
```

## V0.5 — 记忆回廊 (Memory Arcade) 开发提示词（双层模型版）

```text
【角色设定】
你是后端 AI 工程师，专注记忆系统。当前阶段 V0.5：长期记忆与独立记忆检索。

【模型路由与任务分配】
1. 本地 Qwen3.5:4b（主记忆检索与简单更新）：
   - 生成记忆语义检索的查询嵌入（使用 bge-m3 本地生成 embedding，无需 LLM）
   - 对记忆条目进行简单的“重要性”快速初筛（基于规则：如对话中含有“恨”“爱”“秘密”等关键词，标记高重要性）
   - 在 Agent 产生低难度意图（如 greet、wait）时，仅检索并注入记忆摘要，不额外调用云端模型
2. 云端 MiniMax（记忆摘要与深度评估）：
   - 定期（每 10 Tick）对累积的短期对话记忆进行摘要，生成长期记忆片段
   - 评估每条摘要记忆的 importance 分数（0.0~1.0）并生成情感基调描述
   - 当 Agent 产生高难度意图（share, invite, flee）时，基于当前上下文和检索到的记忆，由云端模型整合生成更加丰富的“回忆”叙述

【开发任务】
实现长期记忆归档、语义检索、遗忘曲线、核心记忆保护、角色日记。

【技术要求】
1. 长期记忆归档（memory_archiver.py）
   - 定时器触发（每 10 Tick），收集每个 Agent 的待归档对话。
   - 批量调用云端 MiniMax 进行摘要（系统提示词严格控制输出格式：summary_text, participants, emotion, importance_score）。
   - 本地 Qwen 对归档后的记忆做快速“去噪”：删除与角色身份完全无关的噪音记忆（如纯粹的“嗯”“好的”）。
   - 归档结果存入 Chroma 独立集合 `agent_{id}_longterm`。

2. 语义检索（memory_retriever.py）
   - 使用本地 bge-m3 模型对当前意图的 reasoning 文本生成 embedding，在 Chroma 中检索 Top-5。
   - 本地 Qwen 对检索结果进行一次重排序（rerank），基于相关性和遗忘曲线分数，最终选出 Top-3。
   - 被选中的记忆注入 Agent 的 Prompt（[RECALL] 标签内）。

3. 遗忘曲线（forgetting_curve.py）
   - 实现 score = relevance * importance * exp(-λ * Δt)。
   - λ 根据角色 neuroticism 动态调整，importance 由云端 MiniMax 归档时评估。
   - 本地规则自动删除 score < 0.1 且 importance < 0.2 的条目。

4. 核心记忆保护
   - 若对话导致关系变化幅度 > 0.2，将该对话的摘要 importance 强制设为 1.0，由云端模型在摘要时标记，本地不再参与遗忘删除。

5. 角色日记 API 与 UI
   - GET /agent/{agent_id}/journal，返回最近记忆摘要。
   - 前端旁观界面增加“日记”选项卡。

【输出要求】
- 新增：memory_archiver.py, memory_retriever.py, forgetting_curve.py
- 修改：agent.py（注入长期记忆调用）
- 前端：Diary.jsx 组件
- 测试：test_memory.py 验证归档、检索、遗忘链路
- 所有云端调用通过 LLMGateway，本地调用通过 ollama_client。
```

## V0.6 — 命运纺机 (Fateweaver) 开发提示词（双层模型版）

```text
【角色设定】
你是叙事系统工程师。当前阶段 V0.6：智能叙事注入与世界“意志”，融入 WorldAgent 思想。

   - 生成“触发信号”（如 conflict_opportunity, romance_opportunity），但不生成具体事件内容。
   - 定期（如每 5 Tick）对世界氛围进行简单描述分类（“紧张”、“和谐”、“压抑”）。

   - 当本地检测器触发机会信号且世界氛围符合条件时，调用云端模型生成具体的叙事事件描述。
   - 生成的事件必须包含：事件类型、描述文本、涉及角色、对每个角色的个性化影响提示。
   - 同时对生成事件进行“叙事质量”自检（如提示词要求事件具有意外性、情感张力），不合格则重新生成。
   - 最终事件存入世界大事记，并通过 WebSocket 广播。

实现集体情绪评估、机会检测、叙事事件生成、世界意志配置、事件时间线。

1. 集体情绪评估器（collective_mood.py）
   - 本地 Qwen 仅需简单的数值归纳，不产生 NLP 输出，直接计算平均值和趋势。
   - 将氛围分类结果写入世界状态。

2. 机会检测模块（opportunity_detector.py）
   - 本地规则引擎（不调用 LLM）实时扫描角色位置和关系，生成触发信号。
   - 云端 MiniMax 仅在信号触发后介入。

3. 叙事注入升级（narrative_injector.py）
   - 集成 WorldAgent 思想：WorldEngine 维护 world_will 配置（冲突频率、合作鼓励度、浪漫偏好等）。
   - 云端 MiniMax 生成事件时，将 world_will 作为系统提示，影响事件类型和风格。
   - 生成的个性化影响提示由各 Agent 独立解读（独立 Agent 自主决定如何记忆和反应）。

4. 世界意志配置
   - World 配置 YAML 增加 `world_will` 段，控制冲突频率、合作鼓励度、浪漫偏好等。
   - 本地 Qwen 可对这些参数进行每日动态微调（模拟社会演化），但变化幅度受限。

5. 事件时间线 UI
   - 新增 World Timeline 组件，展示系统事件和角色对话里程碑。

【输出要求】
- 新增：collective_mood.py, opportunity_detector.py, world_will.py
- 修改：narrative_injector.py, world_engine.py
- 前端：Timeline.jsx
- 测试：test_narrative.py 模拟各个机会的触发和事件生成
- 保证双层模型调用正确，本地负责高频监听，云端负责叙事生成。
```

## V1.0 — Athenaeum 正式版 开发提示词（双层模型版）

```text
【角色设定】
你是项目交付负责人。V1.0 最终集成、压力测试、性能调优、文档与发布。

【模型路由与任务分配】
（沿用 V0.7 的双层策略，此阶段重点优化路由效率和健壮性）
- 新增路由缓存：同一 Agent 对同一对象的重复感知推断，返回缓存结果而不调用任何模型。
- 批量本地处理：非紧急意图可以在每个 Tick 内批量调用本地模型（微批处理），提升吞吐。

【开发任务】
全链路集成、稳定性测试、性能优化、文档、发布。

【技术要求】
1. 全链路集成
   - 合并 V0.4~V0.7 功能模块，解决冲突。
   - 验证端到端流程：生成世界 → 启动模拟 → 旁观/附身 → 日记/时间线。

2. 稳定性压力测试
```
