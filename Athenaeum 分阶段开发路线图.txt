文档一：Athenaeum 分阶段开发路线图 (Development Roadmap v1.0)

版本：1.0
日期：2026-05-08
状态：草案
关联 SPEC：Athenaeum 规范文档 v2.0

1. 路线图总览

本路线图将最终 SPEC 拆分为四个可独立交付、可验证的增强型 MVP。每个阶段都有明确的核心风险验证点和体验闭环，遵循“风险前置、纵向切片、架构随需”原则。

text
V0.1 → V0.2 → V0.3 → V1.0
人性火花 → 社交证明 → 世界脉搏 → 故事涌现
2. 版本详细定义

V0.1 – 人性火花 (Soul Spark)

目标：验证单 Agent 人格的一致性、记忆能力与成本基线。

涉及 SPEC 模块：仅 Zyantine 人格引擎的核心决策链。

实现范围：

Agent 内核：硬编码人格配置 (Big Five) + 简化欲望状态 (TR/CS/SA) + 决策引擎（结构化意图的雏形）。
交互：纯文本命令行对话界面，无 EventBus、无数据库。
记忆：仅短期对话记忆（最近 N 条消息）。
不实现：多 Agent、环境、UI、插件架构。
交付物：

一个 Python 脚本，加载 YAML 角色配置，可进行多轮对话。
人格一致性自动化测试（预置 10 个标准问题，检测回答一致性）。
LLM 调用成本统计（单轮 / 单角色日成本估算）。
验收标准：

同一核心问题用 5 种问法，回答的态度/立场偏差 < 15%。
10 轮对话内能准确回忆用户指定的临时信息。
明确后续阶段可承受的成本阈值。
V0.2 – 我和你 (You & Me)

目标：验证两个 Agent 是否能产生有深度、非循环的社交互动。

涉及 SPEC 模块：Agent Mesh 基础、Zyantine 关系演化、用户附身原型。

实现范围：

结构化决策：强制引入意图结构 {intent_type, target, reasoning, mood}，Agent 首先生成意图，再生成对话。
双 Agent 异步对话：使用内存事件通道（无外部 NATS）模拟通信。
关系演化：简单的数值关系（0-1），对话后自动计算增量。
用户交互：命令行旁观 / 附身模式。附身时可注入消息，退出后角色恢复自主。
循环检测：连续 3 轮语义相似度 > 0.7 时自动引入“话题转移提示”。
交付物：

双角色自主对话脚本，可运行 >10 轮不重复。
关系演化日志，验证对话内容与关系变化的因果一致性。
附身介入示例：用户附身后打破关系平衡，观察对方反应。
验收标准：

艾琳与马克连续自主对话 10 轮以上，内容有实质推进。
关系值随对话情绪发生合理浮动。
用户附身说“我其实有点怕你”后，马克下一轮反应与之前明显不同。
V0.3 – 世界的脉搏 (World Pulse)

目标：验证时间、空间、环境对行为的影响，以及长时间运行的稳定性与成本可控性。

涉及 SPEC 模块：WorldX 基础（空间+时间）、环境系统（环境→角色影响）、分级成本调度。

实现范围：

空间系统：不少于 4 个地点的世界模板，角色可移动并相遇。
时间与 Tick 调度：1 现实分钟 = 1 游戏小时，静默 Tick 和重要 Tick 分级调用 LLM。
环境驱动：天气、时间、地点会影响欲望参数（如暴风雨提高 TR），角色产生与环境匹配的行动。
基础 Web 观察界面：仅显示实时状态（位置、当前说话内容），无复杂 UI。
稳定性压力测试：3 个角色持续运行 2 现实小时（约 5 游戏天）。
交付物：

完整 Tick 循环服务，含环境状态更新、角色移动、自动社交触发。
运行日志 + 成本报告。
最小 Web 仪表盘。
验收标准：

3 角色在 5 游戏天内自然移动、相遇、对话，无崩溃。
能观察到一个环境驱动事件（如“暴风雨夜晚，艾琳关窗自语，马克冒雨来访”）。
运行 2 现实小时 API 费用受控于预算线。
V1.0 – 故事涌现 (Emergent Tales)

目标：交付完整产品体验，实现世界生成、丰富叙事与完妥的架构。

涉及 SPEC 模块：全部剩余模块——完整欲望/需求系统、长期记忆与遗忘、关系图谱、世界生成器、叙事注入、插件化架构。

实现范围：

扩展欲望为需求队列，丰富行为动机。
记忆整合与遗忘曲线。
“舞台时间”叙事注入引擎，打破日常琐事。
AI 辅助世界生成（角色+关系+历史交集）。
完妥用户界面与附身管理。
将 V0.3 的经验重构为 SPEC 中所描述的插件化架构。
交付物：交付 SPEC 文档所定义的全部功能。

验收标准：用户可以生成新世界，旁观或附身角色，观察到涌现出的戏剧性社交事件。

3. 架构随需变化原则

接口先于实现：在 V0.1、V0.2 就硬编码核心接口雏形（如 IDecisionEngine），确保后期抽象时不需要改动业务逻辑。
消息契约不可变：V0.2 定义的意图和事件消息 Schema 必须向后兼容，作为 V1.0 正式 EventBus 的基础。
状态版本化：角色存档从 V0.1 起包含 schema_version，升级时只增不减。
