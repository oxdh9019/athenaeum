## 二、各版本规划 vs 实际差异

### V0.4 世界工坊 — 差异分析

| 规划要求 | 实际状态 | 差异 |
|---------|---------|------|
| 世界骨架生成（云端MiniMax） | ✅ 已实现 | 正常 |
| 角色完整配置生成（Big Five/扩展性格/需求/小传） | ⚠️ 部分实现 | **JSON解析频繁失败**，LLM返回的`[THINK]`标签、`turning_points`格式、`needs`格式不兼容 |
| 角色间关系编织（shared_history + 独立视角校验） | ⚠️ 部分实现 | 本地Qwen视角校验逻辑存在但**实际运行中未被调用** |
| 前端审核界面（Big Five雷达图/关系图） | ⚠️ 部分实现 | 雷达图✅，关系图❌缺失 |
| 本地Qwen生成introduce_text | ✅ 已实现 | 正常 |
| Pydantic强校验 + 失败重试 | ❌ 未实现 | 解析失败直接抛出异常，**无重试机制** |
| Token消耗记录 | ⚠️ 部分实现 | `GenerationMetrics`模型存在但**未在API响应中返回实际数据** |

**关键Bug**：
1. `_extract_json` 方法无法正确处理 MiniMax 返回的 `[THINK]...[/THINK][SPEAK]...` 格式
2. `needs` 字段：LLM返回字符串列表 `["belonging", "safety"]`，但 Pydantic 期望 `[{name, level}]`
3. `turning_points` 字段：LLM返回单个字符串，但 Pydantic 期望 `list[dict]`
4. `appearance` 字段：LLM返回字符串描述，但 Pydantic 期望 `CharacterAppearance` 对象
5. `identity_tags.secondary` 字段：LLM返回字符串，但 Pydantic 期望 `list[str]`
6. `social_background` 字段：LLM返回字符串值，但 Pydantic 期望 `dict`

## 三、架构层面问题

### 1. 版本间代码严重耦合

```
v0.4/server.py → import v0.3/server/core/* 
v0.5/server.py → import v0.4/worldsmith.py + v0.3/server/core/*
v0.7/server.py → import v0.5/server/core/* + v0.4/worldsmith.py
```

**问题**：每个版本都依赖前一个版本的代码，形成链式依赖。修改v0.3的代码可能破坏v0.4/v0.5/v0.7。

### 2. WorldEngine 接口不统一

- v0.3 的 `WorldEngine` 有 `_serialize_agents()` 等私有方法
- v0.5 的 `WorldEngine` 重新实现了部分逻辑
- v0.6 的 `OpportunityDetector` 调用 `get_all_locations()` 但该方法不存在
- v0.4 的 `server.py` 直接访问 `_world._tick_id` 等私有属性

### 3. 前端代码重复

- [Worldsmith.tsx](file:///Volumes/Ollama-Models/Athenaeum/v0.4/Worldsmith.tsx) 和 [main.tsx](file:///Volumes/Ollama-Models/Athenaeum/v0.4/worldsmith_client/src/main.tsx) 内容几乎完全相同
- v0.3/client 和 v0.4/worldsmith_client 是独立构建的，但共享同一套组件

### 4. LLM 响应解析脆弱

这是当前**最严重的运行时问题**：
- MiniMax 返回 `[THINK]...[/THINK][SPEAK]...```json...```` 格式
- 解析器无法可靠地提取 JSON
- Pydantic 模型与 LLM 输出格式不匹配
- 没有重试机制

## 五、建议优先级

### P0 — 紧急修复（阻塞基本功能）

1. **修复 LLM 响应解析**：在 `_extract_json` 中正确处理 `[THINK]/[SPEAK]` 标签，增加 JSON 修复逻辑
2. **修复 Pydantic 模型兼容性**：为 `needs`、`turning_points`、`appearance`、`identity_tags`、`social_background` 添加 `field_validator`，自动转换 LLM 返回的格式
3. **添加重试机制**：解析失败时自动重试（最多3次），而不是直接500

### P1 — 重要改进

4. **统一 WorldEngine 接口**：定义公共 API，消除对私有属性的依赖
5. **集成 v0.6 叙事引擎**：将 `CollectiveMood`、`OpportunityDetector`、`NarrativeInjector` 接入 tick 循环
6. **实现核心记忆保护**：在 `MemoryArchiver` 中添加关系变化检测逻辑

### P2 — 架构优化

7. **解耦版本依赖**：将公共代码提取到 `common/` 目录
8. **消除前端代码重复**：统一 Worldsmith 组件
9. **集成 v0.7 Soul 系统**：将目标管理、日程规划、情绪模型接入主流程
